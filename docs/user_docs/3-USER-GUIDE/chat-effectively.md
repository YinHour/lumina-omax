# 高效聊天 — 与你的研究对话

Chat 是你探索式提问和来回对话的主要工具。

---

## 快速开始

1. 进入笔记本 → 点击 Chat
2. 选择要包含的来源（上下文）
3. 输入问题 → 发送
4. 阅读回复
5. 追问（上下文保持不变）

---

## 导览卡片

首次导入来源后，Chat 面板会自动生成一张**导览卡片**（参考 NotebookLM 风格）：

- **标题与摘要** — 基于来源内容生成的概览
- **关键要点** — 文档中的核心信息
- **3 条建议问题** — 点击即可直接发送该问题

导览卡片帮助你在发问前快速了解来源全貌，无需自己想第一个问题。卡片在无对话或导览可用时展示。

---

## 回答后的下一步建议

每次 AI 主回答结束后，Chat 面板会给出 **3 条下一步建议问题**：

- 建议基于本轮你的问题、主回答和笔记本上下文生成，避免泛化或重复
- 点击建议直接发送，复用普通发送路径
- 建议生成在主回答完成后**异步进行**，不阻塞你继续输入下一条问题
- 如果建议生成超时或失败，会提供降级建议，目标是回答后仍尽量给出 3 条下一步
- 建议问题挂在各自最新持久化的 AI 消息上，连续多轮回答不会把上一轮建议复用到下一轮

> **技术细节**：主回答完成后会立即发送 `answer_complete` SSE 事件，恢复发送状态和输入框，同时继续读取同一 SSE 连接中随后到达的建议问题。这意味着即使建议慢或超时，你也可以继续提问。

---

## 上下文管理

上下文控制 **AI 能看到什么**——这是你最重要的控制。

### 三个级别

**完整内容**
- AI 看到：完整来源文本
- 成本：100% token
- 适用：详细分析、精确引用

**仅摘要**
- AI 看到：AI 生成的摘要（非全文）
- 成本：约 10-20%
- 适用：背景材料、参考上下文

**不参考**
- AI 看到：无
- 成本：0
- 适用：机密、不相关、已归档

### 设置方式

Chat → 选择来源 → 勾选/取消 + 选级别 → 保存

> **新来源默认参考全文**：新增来源后默认加入「完整内容」上下文，而不是仅引用见解。

### 笔记本内来源筛选

打开笔记本后，来源栏支持按本次聊天引用范围筛选（标题、文件路径、URL、上传者等），筛选框下方提供「全选 / 取消全选」仅作用于筛选结果。详见 [添加来源](adding-sources.md#笔记本内来源筛选本次聊天引用范围)。

## 流式输出与停止生成

Chat 响应以**实时流式**（SSE）输出，逐字显示——打字机效果：

- **边写边读** — 无需等待全文
- **停止生成** — 流式中点击红色 Stop 按钮取消
- **保留已生成内容** — 取消不丢失已有文本
- **移动端切 Tab 不中断** — 手机端从聊天切到来源再切回，AI 回答继续不中断（三 Tab 全部保持挂载，用 CSS 隐藏替代条件渲染）

---

## 长耗时等待状态

当 AI 处理较慢时，Chat 面板会显示**阶段化等待状态**，让你知道系统仍在工作：

| 阶段状态 | 含义 |
|----------|------|
| 正在获取上下文 | 系统正在构建来源/笔记的上下文 |
| 正在联网搜索 | Tavily 正在检索互联网（如已开启） |
| 正在等待模型响应（{N}s） | 已等待模型首字节 N 秒 |
| 模型已开始输出... | 流式回答进行中 |
| 正在生成建议 | 正在生成 3 条下一步建议问题 |

- 等待秒数实时更新，便于你判断是「工作中」还是「卡死」
- 相同的来源选择下，上下文构建会复用缓存，避免大来源笔记本在统计和发送之间重复构建

## 聊天超时与 llm_timeout 气泡

为避免长时间无响应，笔记本聊天设有超时保护：

- **默认超时 240 秒**（可通过 `CHAT_LLM_TIMEOUT_SECONDS` 调整），覆盖大上下文 + 网络抖动的合理上限
- **心跳事件**：首字节到达前，每 5 秒发送一次 SSE 心跳（可通过 `CHAT_STREAM_HEARTBEAT_SECONDS` 调整），让前端持续显示「正在等待模型响应（{N}s）」

### 超时时的表现

当模型超时，会以 **AI 角色对话气泡**（而非 toast）显示提示：

```
⚠️ 系统提示：

模型响应在 {N} 秒后超时。请尝试：
- 在左侧「来源」栏将不相关的来源切换为「仅参考见解」或「不参考」
- 为本次问题新建一个对话会话后重试

error_code=llm_timeout, timeout_seconds={N}
Server message: ...
```

- **用户提问气泡保留**，输入框立即可继续提问
- **不持久化进会话记忆**：超时时 AI 节点未完成，错误气泡只活在当前页面，刷新后消失，避免污染下一轮 RAG 上下文
- 已流式输出部分内容后超时（少见），错误说明会追加到现有 AI 气泡末尾，不另起气泡

> **范围说明**：心跳与超时当前仅作用于笔记本聊天（`/chat/execute`）。源聊天（`/source/{id}/chat`）、全局 Ask 暂未引入心跳机制。

## 联网搜索（Tavily）

Chat 面板中开启**联网搜索**，让 AI 搜索互联网获取最新信息：

1. 切换 Chat 面板顶部的开关
2. 开启后 AI 可超越上传来源检索实时网页结果
3. 网页结果与本地来源分开引用

需在 Settings → Web Search 配置 Tavily API 密钥。

### 超时与降级

- Tavily 查询设有**超时控制**，超时或异常时返回可读降级消息而非无限等待
- 每个 chat trace 最多调用 Tavily **2 次**（`TAVILY_SEARCH_MAX_CALLS`，默认 2），超过上限后直接返回降级说明，不再触发真实网络请求
- 联网搜索阶段会显示明确状态文案，让用户知道系统仍在处理

### 配额澄清

> **重要**：当模型说「搜索调用次数用完了」**不等于 DeepSeek 或主模型配额耗尽**。这是 Tavily 工具的单次回答调用上限（默认 2 次/回答）或 Tavily 免费档月度配额（1000/月）耗尽时的降级文本。主模型本身没有「检索次数」的本地降级路径。如遇频繁提示，可在 [Tavily 控制台](https://tapp.tavily.com/) 核对当月用量。

---

## 引用格式

Lumiton·Omax 使用内联引用 `[1](URL)` + 末尾 `## 参考文献` 格式：

- 本地来源与网络引用**分开编号**——前端自动探测网络引用编号上限
- 前端后处理兜底：正则补全缺失序号，防御跳号/不带链接/双结尾
- 点击任意编号引用可直接跳转到源材料

## 何时用 Chat vs Ask

| 用 Chat | 用 Ask |
|---------|--------|
| 多轮对话探索 | 一次性综合答案 |
| 手动选择来源 | 自动搜索 |
| 调整上下文 | 跨多来源 |

详见 [核心概念 — 聊天 vs 转换](../2-CORE-CONCEPTS/chat-vs-transformations.md)。
