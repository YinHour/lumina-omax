# AI 上下文与 RAG — Lumiton·Omax 如何利用你的研究

Lumiton·Omax 根据功能不同使用不同方式让 AI 理解你的研究。本节解释 **RAG**（检索增强生成，用于 Ask）和**全文上下文**（用于 Chat）。

---

## 问题：让 AI 感知你的数据

### 传统方案（及其问题）

| 方案 | 优点 | 缺点 |
|------|------|------|
| **微调（Fine-Tuning）** | 模型专业化 | 昂贵、缓慢、不可逆 |
| **全部发送到云端** | 效果好、快速 | 隐私噩梦、数据失控、昂贵 |
| **忽略你的数据** | 私密、免费 | AI 不了解你的具体领域 |

### Lumiton·Omax 的双重方案

- **Chat**：将选定的全部内容发送给 LLM——简单透明，你选来源，AI 看到完整内容
- **Ask (RAG)**：检索增强生成——自动搜索你的内容，找到相关片段，只发送那些部分

---

## RAG 三阶段

### 阶段 1：内容准备

上传来源时系统自动：
1. **提取文本** — PDF / URL / 音频 / 视频 → 文本
2. **分块** — 长文档拆分为约 500 词的片段
3. **向量化** — 每个片段生成语义向量（代表含义的数字序列）
4. **存储** — 片段 + 向量 + 元数据 → 可搜索存储

> **图片也参与向量化**：文档中的图片经 Vision LLM 描述后，描述文本纳入向量嵌入，使图片内容可被语义搜索。详见 [添加来源 — Vision 图片描述](../3-USER-GUIDE/adding-sources.md#vision-图片描述)。

### 阶段 2：查询时

当你提问时：
1. 系统将问题转换为向量
2. 在所有片段中做相似度搜索
3. 返回最相似的 Top 5-10 个片段

### 阶段 3：增强

系统构建 prompt，将检索到的片段注入，LLM 基于这些片段回答。

---

## 两种搜索模式

### 文本搜索（关键词匹配）
- 使用 BM25 排名算法
- 找包含你关键词的片段
- 适合：记住精确短语、找具体名称或数字、需要精确引用

### 向量搜索（语义相似度）
- 将问题转换为向量
- 找语义上相似的片段
- 适合：探索概念、不必知道确切词语、找相关想法

---

## Hybrid RAG：向量 + 知识图谱并行

Lumiton·Omax 的 Ask 模式采用 **Hybrid RAG** 架构，并行执行两类检索：

| 检索方式 | 入口 | 扩展 | 适合 |
|----------|------|------|------|
| **向量搜索** | 问题嵌入相似度 | Top K 片段 | 语义相似内容 |
| **知识图谱（KG）** | BM25 全文命中实体 | 1-hop 子图扩展 | 结构性/实体关系 |

### 知识图谱

- 文档经 LLM 抽取实体与关系，存入 `kg_entity` / `kg_relation` 表
- `kg_entity` 表建有 BM25 全文搜索索引
- `UPSERT` + `slugify` 消歧，保证实体唯一
- Hub Node 超关系建模（如 EXPERIMENT 枢纽节点）

### 设计理念

- 向量检索找「语义相似」，知识图谱找「结构相关」——两者互补
- BM25 命中实体后做 1-hop 子图扩展，发现直接关联但语义不一定相似的内容
- 两路结果并行合并，供最终回答 prompt 参考

> **状态**：KG 链路已部分实现。Vision LLM + KG 全联动仍在路线图中。

## 上下文管理：你的控制面板

| 级别 | 共享内容 | 隐私 | 适用场景 |
|------|----------|------|----------|
| **完整内容** | 完整来源文本 | 低 | 详细分析、精读 |
| **仅摘要** | AI 生成的摘要 | 高 | 背景材料、参考 |
| **不参考** | 无 | 最高 | 机密、不相关、已归档 |

## Chat vs Ask：核心区别

### Chat（全文上下文）
- 你手动选择来源，AI 看到完整内容
- 对话式：多次追问，上下文保持
- 适合：你知道哪些来源相关、想精读分析
- **SSE 心跳与超时保护**：首字节到达前每 5 秒发送心跳，让用户看到「正在等待模型响应」；超时（默认 240 秒）后以 AI 气泡提示而非崩溃。详见 [高效聊天 — 聊天超时](../3-USER-GUIDE/chat-effectively.md#聊天超时与-llm_timeout-气泡)。

### Ask（RAG 自动检索）
- 系统自动搜索所有来源
- 只发送最相关的片段给 AI
- 一次性综合回答，非对话式
- 适合：来源多、不确定哪些相关、需要综合答案
- **检索覆盖统计**：答案附带「来源总数 / 可检索来源 / 本次命中来源」，便于判断覆盖。详见 [搜索指南 — 检索覆盖统计](../3-USER-GUIDE/search.md#检索覆盖统计)。
- **范围说明**：Ask 链路暂未引入 SSE 心跳机制，长链路依赖前端等待状态文案。

---

## 关键设计决策

1. **搜索，而非训练** — 搜索灵活可逆，微调缓慢且永久
2. **显式检索，非隐式知识** — 可验证 AI 看了什么，有溯源链
3. **多种搜索类型** — 不同问题需要不同搜索，给你两种选择
4. **上下文作为权限系统** — 不是所有保存的内容都需要送达 AI
5. **Hybrid RAG** — 向量 + 知识图谱并行，面向科研文献场景兼顾语义与结构
6. **心跳与超时保护** — 长链路 SSE 不应静默无响应，让用户能区分「工作中」与「卡死」

---

## 总结

**Chat（全文）**：手动选源，对话式，透明，有心跳保护
**Ask（RAG）**：自动搜索，一次性回答，高效，附覆盖统计

两者都：保护数据隐私、给你控制权、创建溯源链、支持多个 AI 提供商
