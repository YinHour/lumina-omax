# AI 与聊天问题

---

## 聊天不工作 / 模型不可用

**解决**：Settings → API Keys → 检查凭证 → 测试连接 → 重新发现和注册模型

## API 密钥无效

1. Settings → API Keys → 测试连接
2. 失败 → 去提供商网站获取新密钥
3. 删除旧凭证 → 创建新凭证 → 测试 → 发现模型

## 聊天回复差

- 检查上下文：确认相关来源在「完整内容」模式
- 问更好的问题：具体 > 泛泛
- 换更强模型：gpt-4o 或 claude-sonnet
- 要求引用：「带页码引用回答」

## 聊天太慢

- 换更快模型：Groq、gpt-4o-mini
- 减少上下文来源
- 增加超时：`API_CLIENT_TIMEOUT=600`

## 聊天超时（llm_timeout）

当模型响应超过超时上限（默认 240 秒，`CHAT_LLM_TIMEOUT_SECONDS`），会以 **AI 对话气泡**（而非 toast）显示提示：

- 气泡含本地化操作指引 + 英文诊断段（`error_code=llm_timeout`、`timeout_seconds`）
- **操作建议**：在左侧「来源」栏将不相关来源切换为「仅参考见解」或「不参考」，或新建对话会话重试
- 用户提问气泡保留，输入框立即可继续提问
- 错误气泡**不持久化**进会话记忆，刷新后消失，避免污染下一轮 RAG

> **如何缓解**：减少上下文来源数、用「仅摘要」模式、换更快的模型、或调大 `CHAT_LLM_TIMEOUT_SECONDS`。

## 等待状态显示「正在等待模型响应（N 秒）」但无回答

这是 SSE 心跳在工作——首字节到达前每 5 秒发送一次心跳（`CHAT_STREAM_HEARTBEAT_SECONDS`），让你知道系统仍在处理：

- 若秒数持续增长后最终出答案 → 正常，大上下文/网络抖动导致首字节慢
- 若一直无回答最终触发 llm_timeout → 见上一条
- 实测 11 源 / 127k tokens / 65 条历史的 TTFT 约 6-8 秒，属正常范围

---

## 联网搜索卡死 / 「搜索调用次数用完了」

> **重要澄清**：当模型说「搜索调用次数用完了」**不等于 DeepSeek 或主模型配额耗尽**。这是 Tavily 工具的限制：
> - 每次回答最多调用 Tavily 的次数由设置项管理（默认 5，设置页「联网搜索」可调 1-20）
> - Tavily 免费档月度配额 1000/月耗尽时也返回失败
> - 主模型本身没有「检索次数」的本地降级路径

**解决**：
- 在 [Tavily 控制台](https://tapp.tavily.com/) 核对当月用量
- 如用量耗尽，临时关闭联网搜索开关
- Tavily 查询已有超时控制，不会无限等待——超时后返回可读降级消息

## 移动端切 Tab 后 AI 回答中断

已修复：移动端三 Tab（聊天/来源/笔记）全部保持挂载（用 CSS `hidden` 控制显隐替代条件渲染），切页不再中断流式回答。

- 切到其他 Tab 再切回，回答继续
- 点停止按钮的 `AbortError` 已静默处理，不弹错误 toast

---

## 超出速率限制

- 等 1-2 分钟重试
- 换更小/更便宜的模型
- 降低并发操作
- 用 Ollama 本地模型（无限制）

## AI 幻觉（编造事实）

- 确保来源在上下文中
- 要求引用：「带引用回答」
- 换更强模型
