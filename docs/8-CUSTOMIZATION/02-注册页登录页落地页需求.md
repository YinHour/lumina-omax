# 02-注册页登录页落地页需求

登录体系需要涉及以下页面和状态：

---

## 1. 登录页（改造现有 LoginForm）

| 元素 | 说明 |
|------|------|
| 品牌区 | Lumina™ / Yinshi AI Logo + 标语 |
| 用户名输入 | 取代原来仅有的密码框 |
| 密码输入 | 保留 |
| 登录按钮 | 提交 username + password |
| 注册入口 | 「没有账号？注册」链接跳转注册页 |
| 语言切换 | 已有的 i18n 语言选择器 |
| 错误提示 | 账号不存在 / 密码错误 / 账号待审批 / 账号已禁用 |

**新增错误态**：账号存在但 `status=pending` 时提示「账号等待管理员审批，请稍后重试」而非「密码错误」

---

## 2. 注册页（新增）

| 元素 | 说明 |
|------|------|
| 用户名 | 登录凭据，唯一校验（前端实时查重 + 后端唯一约束） |
| 显示名称 | 可选，用于源列表展示上传者 |
| 密码 + 确认密码 | 两次输入校验一致 |
| 注册按钮 | POST /api/auth/register |
| 成功提示 | 「注册成功，请等待管理员审批后登录」不自动跳转登录 |
| 返回登录 | 「已有账号？登录」链接 |

---

## 3. 管理员审批（新增管理界面）

| 元素 | 说明 |
|------|------|
| 入口 | 仪表盘设置区或独立管理页，仅超级管理员可见 |
| 待审批列表 | 用户名 / 显示名 / 注册时间 / 操作（通过/拒绝） |
| 已拒绝列表 | 可重新批准 |
| 审批 API | `GET /api/auth/users/pending`、`PUT /api/auth/users/{id}/approve`、`PUT /api/auth/users/{id}/reject` |

管理员身份判断：请求中带 `Authorization: Bearer {OPEN_NOTEBOOK_PASSWORD}` 的用户被识别为超级管理员

---

## 4. 涉及 i18n 新增标签

```
auth.loginTitle, auth.loginDesc, auth.loginButton,
auth.registerLink, auth.noAccount, auth.hasAccount,
auth.username, auth.usernamePlaceholder,
auth.registerTitle, auth.registerButton,
auth.registerSuccess, auth.pendingApproval,
auth.passwordMismatch, auth.accountDisabled,
auth.usernameTaken,
admin.pendingUsers, admin.approve, admin.reject,
admin.noPendingUsers,
```

---

## 5. 路由设计

```
/login      → 登录页（改造）
/register   → 注册页（新增）
/admin/users → 用户管理页（新增，仅管理员可见）
```
