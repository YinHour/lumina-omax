# 针对《Lumina™科研助手试用反馈20260509》的回复说明

对反馈文档中的关键事项进行以下说明与更新。

## 一、持续推进及待明确事项的回复

### 1. 登录便捷性
在实现完整的账户系统之前，为了方便研发人员快速访问，您可以为网页创建**桌面快捷方式**。
* **Windows 系统操作说明**：
  1. 在 Chrome 或 Edge 浏览器中打开 Lumina 系统的网址。
  2. 点击浏览器右上角的“三个点”菜单按钮（设置及其他）。
  3. 选择 **“保存并分享”**（或“更多工具”），然后点击 **“创建快捷方式...”**。
  4. 在弹出的对话框中，勾选 **“在窗口中打开”**（这会让应用看起来像一个独立的桌面软件，没有浏览器的地址栏），然后点击“创建”。
  5. 此时您的桌面上就会生成一个 Lumina 的图标，以后只需双击该图标即可快速登录使用。

### 2. 账户权限与多终端隔离
本系统不是第三方多用户系统，但在业务逻辑和数据隔离方面已满足基本的多终端多用户访问，明确目前的“账户权限”机制如下：
1. **多终端访问与页面记忆隔离**：目前的页面配置记忆（例如：笔记本页面对“联网搜索”的开关、来源的“全文/见解”参考范围设置、询问与搜索页面的输入内容，以及语言和主题等）是基于**本地终端浏览器（LocalStorage）**进行记忆的。也就是说，不同设备、不同浏览器之间互相隔离，研发人员在各自的终端上拥有完全独立的偏好设置。
2. **笔记本密码级访问控制**：我们增加了针对敏感项目的访问控制。对于带密码的笔记本，不仅在查看内容时需要输入密码解锁，现在**在删除带密码的笔记本时，也必须进行密码校验**。
3. **超级管理员权限（Master Password）**：针对团队管理，系统新增了前端超级管理员密码功能。掌握管理员密码的人员，可以绕过单个笔记本的密码限制，直接进行删除或管理操作，满足了小团队内基本的数据管理与权限隔离需求。

### 3. 目录结构方案说明
关于目录结构，我们采用以下方案：
* **单个笔记本为最小研究单位**：单个笔记本内部无目录结构，这也是为了保持知识的聚焦，我们不建议在一个普通笔记本内放置过多的来源文件。
* **聚合视角的目录区分**：对于跨领域的复杂项目，可通过“聚合笔记本”功能将多个相关笔记本汇聚。在聚合笔记本内部，我们已经通过不同颜色的多标签视角来清晰展示每个来源属于哪个子笔记本，这本身就起到了目录区分的作用，因此不再需要额外引入繁琐的灵活标签体系。

### 4. 读取性能与格式兼容
关于格式兼容性问题，目前系统**已经实现了全面兼容**：
* 对于传统的 `.doc` 和 `.xls` 等各类 Office 格式文件，系统在底层已实现上传时**自动将其转换为 PDF 格式**。这不仅彻底解决了格式解析的兼容性问题，同时也保证了极高的读取性能。

### 5. 图片识别能力
关于图片和多模态识别：
* 系统目前集成的解析引擎（如 Docling/MinerU 等）已具备基础的文档内插图定位能力。
* 我们正在积极测试与对接多模态大模型（Vision LLM），旨在让系统不仅仅能“看到”图片，还能针对图片内容（如实验数据图表、图纸）进行精准回答，后续有可展示的测试环境成果会第一时间同步。

### 7. 系统稳定性保障
针对“系统稳定有待验证”：
* 我们非常欢迎且感谢贵方在试用中遇到报错时，记录操作步骤与截图。这对于我们快速定位如“高并发处理”、“格式异常中断”等偶发问题非常有帮助。
* 在近期的更新中，我们已经对底层数据库事务（Transaction）进行了加固，大幅降低了之前可能出现的“操作失败但未报错”的隐性 Bug。

### 8. LLM 模型接入
关于模型的丰富度：我们理解您对横向对比不同模型能力的迫切需求。请放心，相关的多模型接入工作**我们将尽快在系统底层进行统一接入和配置，无需使用人员进行任何额外的手动操作或配置**。一旦接入完成，研发人员只需在界面上的模型下拉列表中直接选用即可（包括 DeepSeek、Gemini等），相关进度我们将第一时间同步。

### 9. 智能化工具扩展（白名单方案）
针对联网搜索等工具的扩展，白名单机制已在后台测试中。待贵方提供允许接入或屏蔽的网址来源反馈后，我们会配合进行定向调优，确保大模型生成的外部内容安全、准确。

## 二、新增事项的回复

### 局域网远程登录操作指导
局域网远程访问功能已经实现。研发人员可通过局域网内任意设备的浏览器进行访问。
* **远程访问 IP 地址及端口**：`192.168.9.7:3000`
* **使用方式**：在浏览器地址栏输入 `http://192.168.9.7:3000` 即可直接进入系统。
* **注意事项**：由于局域网环境通常使用 DHCP 自动分配 IP，`192.168.9.7` 这个 IP 地址可能会因局域网 IP 池的定期变动而发生改变。如果某天发现无法访问，请与我们联系确认最新的主机 IP，或建议贵方 IT 部门为部署本系统的服务器分配一个**静态 IP 地址**。

### 聚合笔记本架构说明
**聚合笔记本功能现已上线并优化**。
* **什么是聚合笔记本**：它类似于一个“文件夹”或“总集”，允许您将多个独立的普通笔记本汇聚在一起。例如，您可以把“前端资料”、“后端文档”、“API 设计”三个笔记本聚合为一个名叫“项目核心”的聚合笔记本。
* **与传统笔记本的区别**：传统笔记本直接上传文件；而聚合笔记本本身不直接接收上传的文件，它的内容来源于它所包含的子笔记本的集合。
* **最新体验优化**：我们重点改进了聚合笔记本的视觉体验。当您进入聚合笔记本后，**属于不同子笔记本的来源文件会通过不同颜色的标签被明确标注出来，并且系统会自动将属于同一个子笔记本的来源进行聚类和分组展示**，让您可以极快地在宏观视角下按类查阅大量聚合资料。

### 来源见解的区别与联系
生成见解（Insights）是利用 LLM 模型根据不同的“转换指令（Transformations）”从长文本中提取出的浓缩信息。目前系统可以根据默认指令或您自定义的指令进行多维度提取。
* **使用场景差异**：您可以把它理解为对原文的“摘要”、“关键数据提取”或“Q&A 生成”。不同的见解适用于不同的目的（如快速了解大意，或仅关注实验数据）。
* **最新优化关联**：在此次更新中，全局“询问与搜索（Ask）”界面的底部新增了 **“保存为笔记 (Save to note)”** 和 **“复制 (Copy)”** 按钮。您不仅可以从见解中获取灵感，还可以将对话最终生成的结论一键归档到笔记本的独立“笔记”中，实现“提取见解 -> 提问交互 -> 沉淀为笔记”的完整研究闭环。

### 提问窗口历史记录
全局 Ask 页面的提问功能目前每次提问生成的结果都是一次性的，刷新或关闭即消失，**但现在我们已经支持将有价值的回答直接保留**：
* 提问窗口本身虽然不作为像微信一样的长期流式对话历史保存，但我们在问答结果底部**新增了“保存为笔记”功能**。您可以将任何重要的、有价值的模型回复直接作为一条“笔记”保存到对应的笔记本中长期留存，以备后续查阅或作为其他模型分析的上下文来源。
