# 研发周报 (5.25 ~ 5.31)

## 本周工作总结

本周工作围绕"用户反馈闭环后半程 + 多用户认证系统落地 + 文档体系补全"展开。核心目标是将前两周修复的 P0 问题推向可交付状态，同时补齐认证这一关键基础设施短板，使系统从"单机共享密码"演进到"多用户注册审批"。

以下是按逻辑推进拆分的工作量梳理：

### Day 1 — 文件上传增强：原始文件名与重复检测（5.26 ~ 5.28）

- **原始文件名保留**：`api/routers/sources.py` 增加 `original_filename` 字段，上传接口返回用户本地文件名而非系统重命名后的 UUID 名，提升文件管理可读性。
- **重复上传检测**：新增基于文件哈希的重复检测逻辑，避免同一文件被多次上传造成知识库冗余。
- **标题 Tooltip**：前端上传列表增加完整信息 tooltip 悬浮展示。
- **PR #8 合并**：`enhancement_0526_feedback` → `main`，文件上传体验完整闭环。

### Day 2 — Vision LLM 文档图片语义描述（5.28 ~ 5.29）

- **功能落地**：在文档解析流程中集成视觉 LLM，对提取出的文档图片自动调用多模态模型生成语义描述。
- **增强解析完整性**：此前文档中图片仅作为二进制附件存在，现可被语义检索命中，提升知识库可问答覆盖率。
- **PR #9 合并**：`feat_picture_parse_0528` → `main`。

### Day 3 — P0 用户反馈修复闭环（5.29 ~ 5.31）

- **停止按钮修复（#1）**：前端 `AbortController` 逻辑加固，解决生成中"停止"按钮无响应问题。
- **ASK 准确性优化（#11）**：LangGraph ASK 流程中检索与生成环节调优，提升问答精度。
- **Excel 图片渲染修复（#13）**：修复 Excel 文档中内嵌图片在前端无法正常渲染的问题。
- **Sourcery 审查修复**：错误响应脱敏处理、abortController 空值保护。
- **CI 流程优化**：将 E2E 测试标记为 `@pytest.mark.e2e`，从常规 CI 中排除，避免 CI 超时。
- **PR #10 合并**：`bugfix/user_feedback_0529` → `main`，P0 三项全闭环。

### Day 4 — 多用户认证系统建设（5.29 ~ 5.31，合并于 6.1）

- **认证中间件落地**：基于 JWT 实现完整用户认证中间件，替换此前"单密码兜底"模式。
- **用户审批面板**：新增 `UserApprovalDashboard`，管理员可审批/拒绝新注册用户，实现"注册→审批→使用"的权限分层。
- **HS256 密钥派生**：修复短密钥兼容问题——`JWT_SECRET` 不足 32 字符时自动通过 SHA-256 派生 HS256 密钥。
- **JWT Decode 回退**：`get_current_user_from_state` 增加直接 JWT decode 兜底路径，避免依赖链断裂。
- **Turbopack 兼容**：catch-all 路由 `[[...slug]]` → `[...slug]`，修复 Next.js Turbopack 编译兼容性。
- **前端路径修正**：`UserApprovalDashboard` 改为相对路径 API 调用，消除部署环境硬编码问题。
- **测试环境适配**：为 JWT 认证中间件更新测试 fixture 和 environment。
- **Copilot + Sourcery 审查通过**：两轮 AI 代码审查全部通过后合并。
- **PR #11 合并**：`enhancement_regloginpage_0601` → `main`，认证基础设施正式进入主线。

### Day 5 — 文档体系补全（5.29 ~ 5.31）

- **用户操作手册更新（PR #12）**：覆盖全部二开功能变更，重点补充多用户认证系统的注册/登录/审批操作流程。
- **Help 文档门户**：新增 `/help` 路由，将 `docs/` 目录渲染为 Web 可浏览的帮助页面。
