## 一、上传数据揭示的核心事实

### 1.1 42%的数据是垃圾（重复上传）

269个文件中，**113个是重复上传**。最严重的是"环境友好型减阻剂及其配套水泥浆体系评价报告"，同一份文件被传了43次（28个PDF + 15个DOC）。这意味着：

- Lumina看到的信号被淹没在同质化噪音中
- 证据地图的第一步不是"整理"，而是"去重"
- 研发人员不知道系统里有什么，所以反复上传同样的文件

**→ 闭环方案缺少"阶段-1：去重与资料清理"**

### 1.2 降失水剂确实是最佳试点（但理由更充分了）

现有方案建议以降失水剂为试点。上传数据强烈支持这个判断：

| 指标 | 降失水剂 | 减阻剂（第二多） |
|------|---------|-----------------|
| 文件数 | 65 | 73（但43个是重复） |
| 去重后有效文件 | ~50 | ~20 |
| 时间跨度 | 2019-2026 | 集中在2022前后 |
| 产品演化清晰度 | HX-11L→12L→14L→16L→16S 完整链路 | 单一产品 |
| 报告类型丰富度 | 研发/评价/实验/结题/开题/数据库模板 | 主要是评价报告 |
| 结构化数据尝试 | 4个数据库模板 + 合成实验记录xlsx | 无 |

**结论：降失水剂试点不变，但理由加上"去重后数据量最大、产品演化链最完整"。**

### 1.3 数据形态的关键发现

**好消息：他们有结构化数据的意识，但执行不到位**

- `中高温防沉降降失水剂合成数据库模板.xlsx` × 4份（4份完全相同，都没填数据）
- `降失水剂HX-16L合成实验记录-2025.9.12.xlsx`（有数据，33KB）
- `实验主索引.xlsx`（40KB）、`产品评价结果.xlsx`（62KB）
- 2020年的实验记录全是PDF扫描件（无法结构化查询）

**坏消息：时间线断裂，2022-2024三年没有数据**

- 最晚的实验记录是2025.9（降失水剂HX-16L合成实验记录）
- 2022-2024完全空白 — 这段时间他们可能在忙其他产品线，但降失水剂的研发断了

**→ 这意味着"阶段2（产品-配方-场景映射）"不可能从历史报告中自动完成，需要人工补字段。**

### 1.4 已有的失败模式目录（可直接用于假设生成）

从文件名中可提取他们的已知问题域：

| 失败模式 | 相关文件数 | 涉及产品 |
|---------|----------|---------|
| **沉降/防沉降** | 10+ | HX-16L（中低温防沉降系列） |
| **倒挂** | 6 | HX-16S（中低温倒挂） |
| **包芯/鼓包** | 4 | HX-14L, 通用 |
| **顶部强度不足** | 10+ | ATMP, HX-16S, 大温差缓凝剂 |
| **不同水泥下性能不一致** | 4 | ATMP中试样 |
| **高温稳定性不足** | 3 | 粉剂降失水剂FL34, 聚合物类 |

**→ 闭环方案应该在阶段3（机理假设）之前增加"反模式目录"，让研发人员从熟悉的问题出发，而不是从抽象假设开始。**

## 二、7阶段闭环的修改建议

### 新增：阶段-1 — 去重与资料清理（30分钟）

**为什么需要**：113个重复文件会污染所有后续分析。

**内容**：
- 用文件哈希识别完全重复的文件
- 保留最新/最完整版本，其余归档（不删除）
- 为每个文件打标签：产品线、资料类型、时间、是否可用

**Lumina任务**：
```
请对当前笔记本中的所有来源做去重分析：
1. 识别内容完全相同的文件
2. 对每组重复，标记最新版本
3. 输出去重后的来源清单，包含文件名、产品线、时间、类型
```

### 阶段0修改：问题定义卡 → 做成填空模板（不是写作题）

**现有方案的问题**：假设研发人员能自主回答"成功判据""关键约束"等抽象问题。实际中普通研发人员写不出来。

**修改**：把7个问题改成预填选项的模板：

| 字段 | 预填选项（从他们的数据中提取） |
|------|------------------------------|
| 产品对象 | HX-12L / HX-14L / HX-16L / HX-16S / FS-23L / FL34 / 其他____ |
| 应用工况温度 | 中低温(30-90℃) / 中高温(90-150℃) / 高温(>150℃) |
| 当前不达标指标 | 降失水 / 沉降 / 倒挂 / 包芯/鼓包 / 顶部强度 / 高温稳定性 / 稠化异常 |
| 已尝试方案 | （从证据地图中自动提取已测试的配方列表） |
| 成功判据 | API标准 / 客户指定指标 / 对标竞品____ |
| 水泥条件 | G级/____ 厂家____ 批次____ |
| 成本约束 | 无约束 / 不高于现有配方 / 上限____元/吨 |

**关键变化**：把"写作题"变成"选择题+填空题"，让不会研发方法的普通人员也能参与。

### 阶段1修改：证据地图 → 增加"去重后索引"

增加一个步骤：在分类之前，先用Lumina生成一份"唯一来源清单"，确保不会对同一份文件重复分析43次。

### 阶段2修改：产品-配方-场景映射 → 从反模式出发

**现有方案的问题**：要求从零建立映射关系，但269个文件大部分是报告而非结构化数据。

**修改**：增加前置步骤"反模式目录"——

```
请从当前降失水剂资料中，针对以下已知问题域各整理一份"反模式卡"：
1. 沉降/防沉降 → 哪些配方/条件下出现？与哪些指标相关？
2. 倒挂 → 发生在哪个温度区间？与缓凝性/分散性的关系？
3. 包芯/鼓包 → 与水泥类型、配方版本的关系？
4. 顶部强度不足 → 与温度、水泥批次、缓凝剂搭配的关系？
5. 不同水泥下性能不一致 → 最敏感的配方参数是什么？

每个反模式卡包含：
- 现象描述
- 出现的产品/配方范围
- 已尝试的解决方向
- 仍未解决的问题
```

**为什么这样做**：研发人员最熟悉的是"什么问题反复出现"，从这个切入点引导他们走向假设生成，比让他们凭空做抽象映射容易得多。

### 阶段3修改：机理假设 → 增加"假设质量检查清单"

普通研发人员提出的"假设"往往是"多加一点XX试试"。需要一张检查清单：

- [ ] 假设描述的是一个**因果机制**，不只是一个配方调整方向？
- [ ] 假设**可以被实验证伪**（即存在可观测的"失败"结果）？
- [ ] 假设引用了至少一条**历史证据**？
- [ ] 假设明确了**适用范围**（只在某种水泥/温度/水质下成立）？

不通过检查清单的"假设"退回阶段0重新定义问题。

### 阶段4-5保持：实验矩阵和复盘要加"失败沉淀模板"

实验复盘不能只对比假设和结果。每次失败必须沉淀为：

```
失败知识卡 #001
现象：______________
配方：______________
条件：______________
假设备选（3个）：1.___ 2.___ 3.___
最可能原因：___
排除的实验：___
可复用的规则：如果___，则不应该___。
```

### 阶段6修改：管理层摘要 → 增加"罗庆视角的研发仪表盘"

现有方案的管理摘要面向李勇（经营指标）。但**推动落地的关键人是罗庆**。他需要的是：

- 每条产品线的研发阶段一目了然
- 哪些配方版本在哪个阶段（小试/中试/现场）
- 哪些失败模式已被解决，哪些还在反复
- **研发效率指标**：一个问题从提出到实验矩阵形成需要几天

## 三、落地推动策略

### 3.1 为什么从罗庆切入

- 罗庆是**直接痛点承受者**：他的团队在反复试错，他的kpi是研发产出
- 罗庆**已经尝试过结构化**（合成数据库模板 × 4），说明他有意识但缺方法
- 罗庆**最清楚团队短板**：他知道手下谁缺乏研发思路
- 相比李勇看经营结果，罗庆看研发过程——我们的闭环改的就是过程

### 3.2 罗庆沟通策略

**不要说"我们来教你们做研发"**。说：

"罗总，这轮试用我们发现一个情况：大家上传了很多有价值的报告，但Lumina不知道怎么用这些报告帮你做决策。我们梳理了一下，降失水剂这块你们从2019年到现在积累了50多份资料，HX系列的产品演化也很清楚。**我们想找个半天，跟你团队一起，拿一个你们最近在头疼的具体问题，从头到尾用Lumina跑一遍。不是为了培训怎么用AI，是想看看能不能把你们已有的这些东西，组织成一套可复用的研发思路。**"

**具体安排**（分三步，不要一次搞太大）：

**第一步（本周）：2小时工作对齐 — 只跟罗庆一个人**

- 展示去重分析结果（43份重复文件，给他看效率损失）
- 展示反模式目录（帮他从"问题"角度重新看自己的数据）
- **让他选一个具体问题**作为首轮试点（建议：HX-16L的沉降问题，或者HX-16S的倒挂问题——资料最新最全）
- 约定下周半天，带他团队1-2个人一起跑

**第二步（下周）：半天实战 — 罗庆 + 1-2名骨干**

- 寅时团队主导操作Lumina，欧美克团队提供领域知识
- 按修改后的闭环跑完一轮：
  - 去重（5分钟）→ 问题定义（填模板，15分钟）→ 反模式目录（30分钟）→ 机理假设（30分钟）→ 实验矩阵设计（30分钟）
- 产出一份不超过8组的实验矩阵
- 让欧美克的人**实际去做这几组实验**

**第三步（两周后）：复盘会 — 扩大到唐昌强**

- 跑完实验后回来复盘
- 如果实验矩阵确实帮他们少走了弯路，让罗庆自己跟唐昌强说效果
- 这时再拉李勇进来，展示管理摘要（有了实际数据）

### 3.3 李勇沟通策略

**不要一开始就找李勇**。李勇看的是结果，在还没有结果的时候找他只会让他觉得"又来了一个AI培训"。

**触发时机**：第三步复盘会后，如果第一轮实验矩阵确实产出了有价值的结论，用这个结论约李勇15分钟：

"李总，罗总团队用Lumina跑了一轮降失水剂的研发试点。以前他们试一个新配方方向大概要做XX组实验，这次我们先用历史数据做了反模式分析，锁定了3个最可能的机理假设，第一轮只做了8组实验就找到了关键变量。如果这个模式能复制到缓凝剂和减阻剂，研发周期大概能缩短多少。"

**不要谈AI，谈研发效率。**

### 3.4 风险预案

| 风险 | 应对 |
|------|------|
| 罗庆说"太忙了没时间" | 缩小scope：不搞半天工作坊，2小时的去重+反模式目录演示就够了。让他看到10分钟就能把43份重复文件清掉 |
| 研发人员做不出假设 | 用反模式目录兜底：让他先选一个问题（如沉降），从"以前怎么解决的"开始聊，帮他翻译成假设格式 |
| 第一轮实验矩阵跑不出结果 | 这恰恰证明了"需要方法"——以前乱试跑不出结果是因为没假设，不是Lumina的问题 |
| 李勇不认可 | 不用强推——等罗庆团队自己觉得有用，他们自然会去跟李勇说 |
